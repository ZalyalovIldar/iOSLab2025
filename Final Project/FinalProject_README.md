# 🎓 Финальное задание — iOS Final Project

Итоговое задание по курсу iOS-разработки.  
По этому проекту проходит зачёт: вы должны сдать готовое приложение и защитить свои архитектурные и технические решения.

---

## 🎯 Цель

Создать полноценное iOS-приложение уровня Junior-разработчика, используя основные темы курса:

- SwiftUI
- Navigation
- MVVM + Observation
- Networking
- async/await
- состояния экрана
- локальное хранение
- Dependency Injection
- Swift Package Manager
- UIKit + SwiftUI integration
- тестирование

Приложение должно выглядеть как законченный мини-продукт, а не как набор отдельных экранов.

## 📌 Ожидаемые требования к проекту

### 1. SwiftUI UI

Приложение должно быть написано на SwiftUI.

Обязательно:
- минимум 3 экрана
- разбиение UI на компоненты
- аккуратный внешний вид
- поддержка loading / empty / error / content состояний
- отсутствие бизнес-логики внутри View

Пример экранов:
- список
- детальный экран
- экран добавления / редактирования
- избранное / статистика / настройки

---

### 2. Навигация

Использовать `NavigationStack`.

Обязательно:
- переход со списка на детальный экран
- передача данных между экранами
- корректная back-навигация

Дополнительно можно использовать:
- `TabView`
- `NavigationPath`
- программную навигацию

---

### 3. Архитектура

Использовать MVVM + Observation.

Обязательно:
- `@Observable` ViewModel
- ViewModel отвечает за состояние и пользовательские сценарии
- View отвечает только за отображение
- сетевые запросы находятся в Service-слое
- локальное хранение находится в Storage-слое
- зависимости внедряются извне

### 4. Networking

В приложении должен быть сетевой слой.

Обязательно:
- `URLSession`
- `async / await`
- `Codable`
- проверка HTTP status code
- обработка ошибок

Пример:

```swift
guard (200...299).contains(httpResponse.statusCode) else {
    throw NetworkError.badStatusCode(httpResponse.statusCode)
}
```

Если выбранная тема не требует реального API, можно использовать mock API или локальный JSON, но архитектура должна быть такой, чтобы реальный сервис можно было подключить без переписывания View.

---

### 5. ViewState

Для экранов с загрузкой использовать состояние экрана.

Пример:

```swift
enum ViewState {
    case loading
    case empty
    case content
    case error(String)
}
```

Обязательно:
- loading state
- error state
- empty state
- content state

---

### 6. Локальное хранение

В приложении должно быть локальное сохранение данных.

Можно использовать:
- SwiftData
- CoreData
- UserDefaults
- FileManager

Обязательно:
- сохранение пользовательских данных
- восстановление данных после перезапуска приложения
- отдельный Storage-слой

---

### 7. Dependency Injection

Сервисы должны внедряться извне.

Обязательно:
- протокол сервиса
- реальная реализация
- mock-реализация
- ViewModel получает зависимости через init или Environment

Пример:

```swift
protocol ItemsService {
    func fetchItems() async throws -> [Item]
}
```

```swift
@Observable
final class ItemsViewModel {
    private let service: ItemsService

    init(service: ItemsService) {
        self.service = service
    }
}
```

---

### 8. Concurrency

Использовать современные инструменты Swift Concurrency.

Обязательно:
- `Task`
- `async / await`
- `@MainActor` для ViewModel или методов обновления UI

Желательно:
- `TaskGroup`
- `actor` для кэша или storage
- отмена задач

---

### 9. UIKit + SwiftUI Integration

В проекте должен быть минимум один элемент интеграции UIKit и SwiftUI.

Можно выбрать один вариант:

#### UIKit внутри SwiftUI

Использовать:

```swift
UIViewRepresentable
```

или

```swift
UIViewControllerRepresentable
```

Примеры:
- WebView
- MapView
- UIKit Card
- Image Picker
- кастомный UIViewController

#### SwiftUI внутри UIKit

Использовать:

```swift
UIHostingController
```

### 10. Swift Package Manager

В проекте должен быть использован SPM.

Обязательно один из вариантов:

#### Вариант A

Подключить стороннюю библиотеку через SPM.

Примеры:
- Kingfisher
- Alamofire
- Lottie
- Swift Collections

#### Вариант B

Создать собственный Swift Package.

Примеры:

- `StorageKit`

---

### 11. Тестирование

Проект должен быть покрыт тестами максимально полно.

Минимально ожидается тестирование:
- успешной загрузки данных
- обработки ошибки
- empty state
- фильтрации / поиска
- сортировки
- добавления данных
- удаления данных
- сохранения данных
- восстановления данных из storage

Обязательно:
- использовать mock-сервисы
- тестировать ViewModel
- тестировать Storage / Service там, где это возможно
- использовать async tests для async-кода

Пример:

```swift
func testLoadItemsSuccess() async {
    let service = MockItemsService(result: .success([Item.mock]))
    let vm = ItemsViewModel(service: service)

    await vm.load()

    XCTAssertEqual(vm.items.count, 1)
}
```

## ✅ Критерии приёмки

Проект принимается, если:

- приложение запускается без ошибок
- реализовано минимум 3 экрана
- используется SwiftUI
- используется `NavigationStack`
- используется MVVM + Observation
- View не содержит бизнес-логику
- есть сетевой слой или mock API со структурой реального сервиса
- используется `async / await`
- проверяется HTTP status code
- реализованы loading / empty / error / content состояния
- есть локальное хранение
- данные восстанавливаются после перезапуска приложения
- используется Dependency Injection
- есть mock-реализации сервисов
- есть минимум один UIKit + SwiftUI integration элемент
- используется SPM: сторонняя библиотека или собственный package
- проект максимально покрыт тестами
- тесты запускаются и проходят успешно
- код структурирован и читаем
- Вы можете объяснить свой код и архитектуру
